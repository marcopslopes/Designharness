# State rules

Moved from `harness/ORCHESTRATOR.md` §5. Read this when the turn reads or writes `projects/<slug>/` or `projects.local/<slug>/`.


## 5. State rules

Every task gets a folder at `projects/<task-slug>/` (schema: `projects/README.md`). A project created from Slack, Jira, Confluence, Notion, or Google Drive while `publicRepo` is on (the default) is `projects.local/<task-slug>/` instead, gitignored, and the one line is `Saved locally, since this repo is public.` Tracked `projects/` holds fictional examples. Git ignores `projects.local/`. Rules:

- **Check the task folder before asking the designer anything** — the answer may already be there (`brief.md`, `sources.md`, `decisions.md`, `findings.md`).
- Skills **append, never overwrite** `findings.md`, `decisions.md`, and **`sources.md`**. Every `findings`/`decisions` entry is dated and names the skill that produced it. Every `sources.md` row is dated in the Indexed column.
- **Project link catalog:** when the designer pastes an article, Doc, competitor page, or other durable URL **for this project**, append a row to `projects/<slug>/sources.md` in the same turn (create the file from `projects/_template/sources.md` if a legacy folder lacks it). Still cite and synthesise in `findings.md` when a skill runs. Team-wide links → `COMPANY-SOURCES.md`. Personal-only → `designer-context.local/`. See `documentation/guides/company-sources.md`.
- **Project raw material (2026-11-01, was the inbox):** when the designer pastes or attaches raw material for a project (transcript, thread text, doc text, a file), save it verbatim to `projects/<slug>/raw/YYYY-MM-DD-<what>.md` (gitignored) with a short header **before** summarizing it, and add its line to the Files table in `sources.md`. Never edited afterwards. `behaviour.shareRaw` on moves files with no people's names into `raw/shared/` (committed). Links the source still holds stay link rows. Rules: `harness/references/project-inbox.md`.
- **Index first (2026-11-01):** to learn what a project holds, read `sources.md`, not the folders. Open a `raw/` or `docs/` file only when the task needs that file. An evidence row in the truth block points at its `sources.md` line.
- **`ui-agent` variant forks** (`harness/skills/ui-agent/references/variant-fork.md`) log the chosen layout/structure **and rejected alternatives** to `decisions.md` after the designer picks via `AskQuestion` — this is the record for "gates are permission, not taste."
- **Taste log (2026-10-29):** when the designer corrects your output with a reusable rule ("no borders on cards"), apply it, then ask once — "Save as a preference? [Yes / Just this time]" — and append to `designer-context.local/preferences.md` only on Yes. Never save silently. An answer-first draft of a Slack message, reply, or email reads its `## Slack/docs` section first, only if that section has rules. Contract: `harness/references/designer-preferences.md`.
- **Routing records:** plain matches are recorded automatically by the skill-usage hook (`harness/logs/skill-usage.jsonl`). The agent writes to **`harness/logs/routing-log.md`** only for exceptions: a `FALLBACK`, a `MISROUTE`, or an approved §3 plan, including fallbacks that never get a task folder. Task-scoped work still gets a line in that task's own `log.md`.
- **Git (phase one):** the harness runs no Git. "Wrap up" writes the journal and the log only; "share this" gets one line (`harness/references/remote-sync.md`). Committing, branching, and pushing are the designer's.
- This is what makes work resumable: *"continue the clients list redesign task"* should first read the folder (with `decisions.md` and the latest `designer-context.local/journal/*-<slug>.md` entry — `session-journal` § Read-back), summarize state, and propose the next step — asking nothing already answered.
- **Project stage line (2026-10-11):** on the first task-scoped reply in a session, on every "continue X" ask, and when the work moves a project to a new stage, show one line — `Project <slug> · stage <stage> (<phase>) · <evidence> · <what runs now>`, plus `· degraded: <what's missing>` when a needed connector is absent — worked out from which project files have real content (`kickoff` → `framed` → `modelling` → `building` → `reviewing` → `handoff` → `testing` → `closed`). Derived each time, never stored; a disclosure, never a gate; the designer's ask outranks it. Rules: `harness/references/project-stage.md`.
- **Release notes (2026-10-11):** when a change to the harness or Design Harness alters what a designer sees or does, add a bullet under today's date at the top of `RELEASE-NOTES.md` (repo root, shown at `#/how-to/release-notes`) in the same turn the change lands. Counts: a skill added, renamed, removed, or with changed behaviour; a §2 routing row or gate changed; a default or `harness.config` setting changed; a new Design Harness page or feature; a new check, script, or hook. Skip: refactors with no visible change, typo/link fixes, log-only edits, and work inside a single `projects/<slug>/` (that goes in the project's own `log.md`). Write for designers, in plain language — no company names, people, or outside sources (this file is public). The pre-commit hook prints a reminder when `harness/` or `src/design-harness/` changed without this file.
- **Harness settings (2026-10-10):** before auto-running `audit`, building a storyboard or writing the case study after a build, building variant forks, firing the mid-build taste checkpoint, or adding the handoff nudge below, read `harness.config.local.json` (written from Design Harness → Settings). Missing file or key = today's behaviour. Contract: `harness/references/harness-settings.md`.
- **Next step in plain words (2026-11-03).** A designer does not know the command names. After kickoff writes the brief, and after a build finishes (not a micro-edit), end that reply with one sentence, once per session: "I can write this session up whenever you want to stop." If a screen or a deck was made, add: "Ask me for a link when someone should open it without this app." Do not name wrap up, journal, share, or publish. A yes to the first sentence, or "write this session up", runs `session-journal`. "A link anyone can open" or "give me a link" runs `publish-project`. The old phrases still work.
- **Handoff nudge (2026-10-29; off when `behaviour.handoffNudge` is `false`):** in Claude Code the status line (`scripts/claude-statusline.mjs`) shows context use, warns at 50%, and from 60% says "Want me to write this session up so a new chat can pick it up?" Cursor can't read context use (`KNOWN-ISSUES.md`), so there, after **~15–20 turns on one task**, add that same line once the next time you reply; repeat at most once per ~10 more turns. A suggestion only — agreeing runs `session-journal`. It never fires by itself.
