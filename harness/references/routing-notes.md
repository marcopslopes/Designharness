# Routing notes — one entry per route

The long notes for every route in `harness/ORCHESTRATOR.md` §2 and
`harness/references/routes.md`: boundaries, modes, and the dated misses
behind each rule. This file has no trigger phrases. Triggers for common rows
live in ORCHESTRATOR §2. Triggers for group rows live in `routes.md`. Each
entry here is keyed by the route name in the Chain column, so Grep the skill
name. When you change a row's triggers, edit only that one file. When you
change its notes, edit only this file.

Read the matched entry here before running its skill. Then read the matched
`harness/skills/<name>/SKILL.md` in full before executing. Kickoff:
`harness/skills/design-kickoff/SKILL.md`.

## Framing and strategy

| Route | Notes |
|---|---|
| Wayfinding | Write the decision map in `decisions.md` only. No brief. No build. Not kickoff. |
| `diagnostic` | Rapid audit across all design layers (research/domain, user needs, strategy, conceptual model, interaction structure, surface) to identify the bottleneck — the lowest layer with unresolved or risky decisions — and recommend which skill to run next. Not a deep dive (that's what individual skills do). Rates each layer Strong/Partial/Assumed/Weak/Not started, flags assumed layers (treated as done but not verified), considers constraints. Front-door triage. See `harness/skills/diagnostic/SKILL.md`. |
| `org-pack-builder` | Builds `context/org-pack.local/` (company context, **domain vocabulary (Layer 2)**, voice, patterns, squads, archetypes, sources) via three modes: MCP extraction (auto-extract from the connected tracker, docs tool, chat, and Figma — recommended), guided interview, or file upload. "Add this…" + one doc → § Add a file (merge into a standard file or new self-describing extra, asks first). Called automatically from onboarding (Step 3.5) when org-pack missing. See `harness/skills/org-pack-builder/SKILL.md`. |
| `design-rationale` | Documents an *already-made* decision — options considered, sourced evidence, reasoning, trade-offs accepted, validation plan — for a record that survives being questioned later. Different from `ux-pattern`'s decision framework mode (that weighs options *before* a pick; this documents *after*). A11y-specific decisions/tradeoffs/eng handoff → `accessibility-decisions`. Logs to `projects/<slug>/decisions.md`. See `harness/skills/design-rationale/SKILL.md`. |
| `product-strategy` | Builds Opportunity Solution Trees (OST) and other strategy frameworks connecting user opportunities → business outcomes → solution bets → experiments. Makes outcome → opportunity → bet → experiment explicit. Groups opportunities by journey moment, generates multiple bets per opportunity (resist early convergence), names riskiest assumption per bet, designs cheapest experiments (days not months). Also supports Impact Mapping, Kano, HEART/North Star, Wardley, Jobs Portfolio. Often called within `design-kickoff` Step 1/2. Feeds `roadmap-prioritization`. See `harness/skills/product-strategy/SKILL.md`. |
| `roadmap-prioritization` | Ranks already-named design tasks on evidence strength, goal fit, and honest effort — shows the reasoning behind the order, never a bare ranked list. Uses `workload-agent` for what's already committed and `okr-goal-setting`'s output as a goal-fit input when one exists. Does not decide *what to build* (`design-kickoff`). See `harness/skills/roadmap-prioritization/SKILL.md`. |
| `okr-goal-setting` | Writes an objective + falsifiable key results tied to a real, sourced business priority — refuses to invent baselines/targets that aren't actually instrumented, and flags gameable metrics. Feeds `roadmap-prioritization`'s goal-fit axis. See `harness/skills/okr-goal-setting/SKILL.md`. |
| `stakeholder-alignment` | Maps every real stakeholder, what each actually optimizes for (sourced vs. inferred, labeled honestly), and the real shape of the disagreement (risk/scope/precedent/unstated cost) — drafts sequenced asks, never sends without an explicit go. Different from `manager-1on1-prep` (manager-gated, one-report status) and `design-rationale` (documents *after* alignment, not before). See `harness/skills/stakeholder-alignment/SKILL.md`. |

## Research and evidence

| Route | Notes |
|---|---|
| `synthetic-user-testing` | In-character task walkthroughs using real personas/archetypes — advisory only; never claims validation or replaces `usability-test-guide`. See `harness/skills/synthetic-user-testing/SKILL.md`. |
| `inspiration-scouting` | Aesthetic/interaction references with take/leave — different from `competitor-scan` (named competitor facts) and `benchmark` (scored the company gaps). Does not invent Foundations tokens. See `harness/skills/inspiration-scouting/SKILL.md`. |
| Research method | One method from the real constraints. Not a menu. Not kickoff. |
| `assumption-mapper` | Separates sourced "known" from unsourced "believed," across user/problem/solution/business buckets, before research or a build starts. Composed into `design-kickoff` Step 0/1 (before the PRD drafts); standalone on an approved task when a new open question surfaces mid-flight. Never says research "validated" an assumption — only explored/supported/contradicted. Feeds `design-kickoff` Step 1.5. See `harness/skills/assumption-mapper/SKILL.md`. |
| `research-question-sharpener` | Diagnoses shallow/jargon/future-based/leading/positive-only questions, rewrites via TEDW + transformation rules, flags what qualitative research can't answer at all (redirects to A/B test, survey, pricing study). Prioritizes with the requester, not for them. Feeds `usability-test-guide`. See `harness/skills/research-question-sharpener/SKILL.md`. |
| `usability-test-guide` | Builds a session-ready quant (task success/time/SEQ/SUS) or qual (TEDW screen-by-screen) usability test guide. Fires from `design-kickoff` Step 1.5's method recommendation, or standalone on an approved task with a Design Harness prototype ready to test. Does not build the prototype (`ui-agent`) or run/synthesize the session (`research-agent` verdict synthesis mode). See `harness/skills/usability-test-guide/SKILL.md`. |
| `research-synthesis` | Read the skill before answering. A paste already in the chat is not an exemption (2026-10-31 benchmark: the interview prompt was answered in 3 steps with no skill, because the answer-first line led with "answer directly"). Tags and clusters raw session data. Feeds `insight-writer`. See `harness/skills/research-synthesis/SKILL.md`. |
| `insight-writer` | Writes key-learning + why + consequence insights from a pattern, distinguishes insights from findings/observations/bugs, and runs a 5-question so-what check + report-level checks before anything ships. Takes patterns from `research-synthesis`. See `harness/skills/insight-writer/SKILL.md`. |
| `screener-builder` | Builds a behavior-first (not demographic-first) recruitment screener — 5-10 questions, knockout logic, ordered so unqualified people are screened out early. Feeds `usability-test-guide` / `research-synthesis` once recruiting starts. See `harness/skills/screener-builder/SKILL.md`. |
| `decision-first-research` | Names the decision, the risk if wrong, what's already known, and the one blocking unknown before picking a method — produces a Decision Brief + an evidence-formula sentence. Fires before `design-kickoff` Step 1.5 when the request itself is still vague/time-boxed. Never used for generative/exploratory work — says so explicitly instead. See `harness/skills/decision-first-research/SKILL.md`. |
| `ia-methods` | Plans/analyzes card sorting (mental-model categorization) and tree testing (findability by label/hierarchy). Card sort before tree test when both are needed. `design-kickoff` Step 1.5's "card sort / tree test" method-menu line routes here. See `harness/skills/ia-methods/SKILL.md`. |
| `research-artifacts` | Turns synthesized research (or a named `COMPANY-ARCHETYPES.md` entry) into a persona, empathy map, journey map, **ability-spectrum** map, **job stories**, or **service blueprint** — six modes, one skill because they share sourced-data-only rules. Never invents personas, disability lived experience, jobs, or backstage/support-process rows (mark unknown, name who to ask). Situational the company contexts OK when labeled. Service blueprint (Mode 6) traces a journey map's pain point to its operational root cause — requires a journey map underneath. A11y *decisions*/eng handoff → `accessibility-decisions`. Opportunity trees / bets → `product-strategy` (consumes jobs, does not write them). See `harness/skills/research-artifacts/SKILL.md`. |
| `research-summary` | Post-session summary (one interview/UT) or executive topline (3–5 consequence-focused insights). Session mode feeds `research-synthesis`; topline feeds `research-shareout` / `deck-builder`. Does not write full insights (`insight-writer`) or the live share-out plan (`research-shareout`). See `harness/skills/research-summary/SKILL.md`. |
| `research-shareout` | Audience-first share-out plan (TL;DR → findings → recs → next steps) plus optional creative formats. Takes finished insights/toplines as input; does not build the HTML deck (`deck-builder`). See `harness/skills/research-shareout/SKILL.md`. |
| `workshop-whiteboard` | Timed research-scoping board for workshops (problem → goals → method → recruit → timeline). Adapted for workshop facilitation, not interview prep. Often hands off to `decision-first-research` or `design-kickoff` Step 1.5. See `harness/skills/workshop-whiteboard/SKILL.md`. |
| `research-agent` (lightweight gap-fill mode) | Single-source synthesis appended to that task's `findings.md`/`sources.md` — no docs draft, no PRD scaffold. Net-new topic with no approved task still hits `design-kickoff`'s front door instead. See `harness/skills/research-agent/SKILL.md` § Lightweight gap-fill mode. |
| `research-agent` (verdict synthesis mode) | Combines whatever qual (usability notes, feedback) and quant (a metric, an A/B number) signal actually exist into one verdict — never fabricates a quant number. Appends to an existing `testing/test-plan.md`'s Results section if one exists, otherwise straight to `findings.md`. See `harness/skills/research-agent/SKILL.md` § Verdict synthesis mode. |
| `competitor-scan` | Targeted reference pull for one named competitor + one feature — uses Mobbin only if a designer already has it connected (optional, never required), web search otherwise. Does not fire on a vague "what's out there" (no named competitor). Never judges the company's own screens — see `benchmark`. See `harness/skills/competitor-scan/SKILL.md`. |
| `benchmark` | Explicit, requested gap analysis of a real existing screen against 2-3 best-in-class examples (calls `competitor-scan` for named competitors), scored on an explicit rubric. Cross-checks every flagged gap against `COMPANY-PATTERNS.md`/`COMPANY-ARCHETYPES.md` before calling it a gap. Never fires automatically. See `harness/skills/benchmark/SKILL.md`. |

## Explore and structure

| Route | Notes |
|---|---|
| `ux-pattern` (structure review) | Structure review, no build step. |
| `ux-pattern` (breadboard mode) | Text-based flow notation (places/affordances/destinations/content) before visual form — Shape Up breadboarding. Uses `conceptual-model`'s objects/vocabulary if that exists. Saves to `projects/<slug>/breadboard.md`. Different job from the row above (drafts a new flow vs. reviews an existing one). See `harness/skills/ux-pattern/SKILL.md` § Breadboard mode. |
| `conceptual-model` | Defines product objects, relationships, states, vocabulary independently of interface. Most load-bearing layer. Includes temporal decisions (history, deletion, intermediate states, lag), OOUX failure modes (shapeshifter/masked/broken/isolated), technique library (noun foraging, object definition, ERD, state diagrams, action inventory, ubiquitous language). Runs after `design-kickoff` (problem defined), before `ui-agent` (building screens). Skip when objects are obvious. See `harness/skills/conceptual-model/SKILL.md`. |
| `conceptual-model` (domain-mapping mode) | Earlier and looser than object decisions: concept maps, terminology audits (synonym vs polysemy), bounded-context mapping, domain event storming, noun harvest — feeds Step 1's noun foraging. **Record contradictions; don't settle them**; that choice belongs to the object-model step, not here. Skip when the domain is already uncontested. See `harness/skills/conceptual-model/references/domain-mapping.md`. |
| `ux-pattern` (decision framework mode) | Weighs existing options against explicit criteria (JTBD/archetype fit, the company pattern consistency, build cost, business goal, risk) — a defensible recommendation with reasoning shown, never a numeric black box. Different from ideation (generating new options) and critique (judging one option alone). Logs to `decisions.md` — same record `ui-agent` variant-fork writes to. **When options are visual/screen-level, hands off to `ui-agent`'s review-board format for the actual artifact** (real precedent: `invite-friends`'s 4-section variant board) — the criteria table stays as the reasoning trail underneath, not a competing deliverable. See `harness/skills/ux-pattern/SKILL.md` § Decision framework mode. |
| `ux-pattern` (debate mode) | Advocate-vs-advocate briefs (JTBD, pattern, build cost, risk, inclusion lenses) then designer picks — different from decision framework's neutral criteria table. Premature-consensus antidote. Logs pick to `decisions.md`. See `harness/skills/ux-pattern/SKILL.md` § Debate mode. |
| `ux-pattern` (grill mode) | One question at a time, branch by branch. Reads the repo and task folder when the answer is already there. Stops when the designer confirms a restatement, logged to `decisions.md` under the decision's name. Debate argues both sides; decision framework weighs a criteria table; critique writes findings. See `harness/skills/ux-pattern/SKILL.md` § Grill mode. |
| `ux-pattern` (go-wide mode) | Chain: one question up front (variation type, which is also the plan go), then ideas from the research grouped into 3 directions, built into the real screen by `ui-agent` and shown by `presenter` as a Compare section beside Today (a name and one-sentence why per frame), then one question at the end about which direction becomes the screen. "Help me think through" is structure/options grounded in the company patterns. `research-agent` only if they explicitly want a fresh discovery sweep. **Never freestyle a brainstorm.** Two questions total. Never a pick from a text list. Plan block: `harness/references/plan-gate.md` § Go wide. Net-new "ideas for X" with no PRD still hits **`design-kickoff`** (front door) — this row is the APPROVED-task remainder hole after MR #26. |
