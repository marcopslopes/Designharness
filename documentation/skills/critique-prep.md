# critique-prep

Presenter script for a group design critique — not a critique of the work.

## What it does

Turns your Figma (plus a brief, BRD, or docs page if you have one)
into a short script you can say out loud:

1. **Frame** — user goal, business outcome, what you want to learn, what's off the table
2. **Walk order** — 3–6 beats, what to say, what not to dwell on
3. **Feedback ask** — one line to paste into the critique sign-up
4. **Lenses to invite** — a stage-matched subset, not the full checklist
5. **Capture sheet** — blank rows for live notes
6. **Sign-up row draft** — in chat only; nothing publishes unless you ask

## When to use

```
"Prep me for critique Thursday"
"Critique presenter script for this Figma"
"Help me present this in UX review"
"Frame this for design critique"
```

Not this skill:

- "Any thoughts on this Figma?" → written critique (`ux-pattern`)
- "Annotate the canvas" → `figma-ux-audit`
- "Write a case study of this project" → `writing`
- "Make a deck" → `deck-builder`

## How it works

1. Drop the Figma URL (required) and any brief or docs link.
2. Muse writes a 15–20 min speakable script (default).
3. The same block is appended to `projects/<slug>/findings.md`.
4. If the file is huge, you'll be asked which frames — it will not script the whole file.

If you also want a critique of the work, say so. That's a separate pass
(script first, then review) so the script doesn't turn into a defense of
findings.
